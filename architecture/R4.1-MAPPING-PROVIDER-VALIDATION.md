# Explore Luxembourg 360 — R4.1 Mapping Provider Validation

**Status:** CLOSED / APPROVED  
**Parent:** R4 — External Infrastructure & Providers  
**Decision update:** 2026-09-02 — Géoportail / ACT adopted as Primary Geospatial Provider

## Purpose

Validate the mapping/provider strategy for the first vertical slice while preserving the approved provider-independent geospatial architecture.

## Core decision

Explore Luxembourg 360 adopts **Géoportail / ACT as the primary geospatial provider** for Luxembourg territory data and geospatial infrastructure.

This is a **preferred provider decision, not an architectural dependency**. PostgreSQL/PostGIS remains authoritative for project-owned geographic data. External sources/providers are accessed through an internal geospatial abstraction boundary so complementary or fallback providers can be introduced without redesigning the product domain.

The decision aligns with the project's Luxembourg-first identity and the principle of using strong national resources where they are technically and legally appropriate.

## Provider roles

### Géoportail / ACT — Primary Geospatial Provider

Géoportail / ACT is the preferred primary provider for official Luxembourg geospatial capabilities relevant to Explore Luxembourg 360, subject to dataset-specific licensing and technical validation.

The confirmed integration surface includes:

- Open Data WMS / WMTS;
- Public Map Layers WMS;
- Vector Tiles;
- OGC API Features;
- JavaScript API;
- 3D resources;
- official orthophotography and other catalogue datasets where permitted.

The exact reuse conditions must be checked dataset by dataset through the GéoCatalogue, including producer, licence, attribution and special conditions. The 2026-09-02 ACT response confirms that these conditions can vary by dataset.

### PostgreSQL / PostGIS — Project-Owned Geographic Authority

PostgreSQL/PostGIS remains authoritative for Explore Luxembourg 360-owned geographic data, including project Places, Routes, curated geometries and other domain-owned spatial content.

External official data is not automatically copied into PostGIS; ingestion depends on the dataset, licence and product need.

### Google Street View — 360° Experience Provider

Google Street View remains the principal external provider for the **360° Experience layer**, especially route-related 360 experiences and global visibility.

The project would prefer a suitable local/national route-360 service if one becomes available, but Google is currently the stronger practical choice for visibility and ecosystem reach.

This is deliberately separate from the primary geospatial-provider decision.

### Mapbox / MapTiler — Secondary / Fallback Candidates

Mapbox and MapTiler remain approved secondary or fallback candidates behind the abstraction boundary. They are no longer the default primary direction.

They may be introduced where they solve a concrete requirement not adequately covered by the primary stack, improve resilience, or provide a justified capability/cost advantage.

### OpenStreetMap — Open Geographic Ecosystem / Source

OSM remains an important open/community geographic data source. Public OSM tile servers are not treated as production tile infrastructure. Any OSM-derived service must respect its applicable attribution, caching, capacity and usage policies.

## Architectural boundary

The approved conceptual architecture is:

**Explore Luxembourg 360 → Geospatial Abstraction Layer → Géoportail / ACT (primary) + complementary providers/sources**  
**Explore Luxembourg 360 → PostgreSQL/PostGIS (project-owned geodata)**  
**Explore Luxembourg 360 → Experience Provider Boundary → Google Street View + Explore 360 own 360° content**

The distinction between these concerns is intentional:

1. **Territory / geospatial infrastructure** — Géoportail / ACT and complementary geographic sources.
2. **Project-owned geographic authority** — PostgreSQL/PostGIS.
3. **Experience / editorial content** — Explore Luxembourg 360.
4. **External 360° experience** — Google Street View and future complementary providers.

## MUST HAVE — first vertical slice

- Web/mobile map rendering.
- Project-owned Place and Route geometries from PostGIS.
- Required official Luxembourg layers where available and permitted, prioritising Géoportail / ACT.
- Basic map interaction and required layers.
- User location display when permission is granted.
- A clean boundary to the Google Street View Experience.
- Provider abstraction so the primary provider can be complemented or replaced without redesigning the domain model or R3 experience.
- Dataset-level licensing, attribution and reuse checks before production use of official external data.

## SHOULD / FUTURE — not automatic MVP scope

- Advanced routing.
- Advanced geocoding/search.
- Permanent geocoding storage from third-party providers.
- Automated map matching beyond the concrete route-production need.
- Elevation services.
- 3D terrain.
- Advanced navigation.
- Provider-specific premium features.
- Additional external providers where a concrete gap or resilience requirement is demonstrated.

A provider's feature catalogue must never silently expand product scope.

## Géoportail / ACT capability classification

### MUST / first-slice priority

- Vector Tiles for performant modern map rendering where the selected official style/layer set meets the UX requirement.
- Required official Luxembourg layers through appropriate WMS/WMTS/vector services.
- OGC API Features for concrete geographic feature retrieval/use cases where applicable.
- Official orthophoto or equivalent imagery where the product experience requires it and dataset licensing permits reuse.
- Metadata/licensing validation through the GéoCatalogue for every externally reused dataset.

### SHOULD / targeted use

- JavaScript API where a specific cartographic integration capability is better served by it than direct service integration.
- Public Map Layers WMS where dynamic public layers are required and performance is acceptable.
- Additional official datasets for discovery, environment, transport, terrain, heritage or other domains when they add a validated product capability.

### FUTURE / selective use

- 3D resources and terrain visualisation.
- More advanced official geospatial feature integration.
- Deeper institutional integration/collaboration if formally established.

### NOT AUTOMATIC MVP SCOPE

The existence of a Géoportail service does not automatically require its integration. Each service must pass the product-need, technical-fit and licensing/attribution test.

## Free-first / cost-controlled rule

The project continues to prefer free, open-source and free-tier options when they satisfy the approved requirements. Paid services are introduced only when a concrete product requirement, commercial licence, reliability need or scale constraint justifies the cost.

The selection of Géoportail / ACT as primary does not create an assumption of zero operational cost; technical usage, hosting, caching and any dataset-specific conditions must still be validated.

## Provider abstraction rule

Provider-specific SDKs/APIs must not leak through Product/UI/domain contracts. The application should depend on internal capabilities such as map rendering, layers, geocoding or routing interfaces, with provider adapters behind that boundary.

**Preferred Provider ≠ Architectural Dependency.**

## External validation status

The 2026-09-02 Géoportail / ACT response materially closes the previously pending external validation for the provider strategy at the architectural level.

ACT confirmed the available external application services and directed the project to dataset metadata/GéoCatalogue for licence, attribution and special-condition checks. Photography, privacy/right-to-image, private-property and drone matters remain outside Géoportail support and require the competent authorities where applicable.

The response does not constitute a partnership, endorsement or blanket licensing approval. Concrete datasets/services must still be validated individually before production reuse.

## Final decision state

**Primary Geospatial Provider: Géoportail / ACT.**

**360° Experience Provider: Google Street View, with Explore Luxembourg 360 own 360° content as the proprietary experience layer.**

**Project-owned geographic authority: PostgreSQL/PostGIS.**

**Secondary/fallback geospatial candidates: Mapbox / MapTiler.**

**Open geographic ecosystem/source: OpenStreetMap.**

The project may now proceed from this clear Luxembourg-first baseline while retaining provider independence and explicit separation between geospatial infrastructure and 360° experience infrastructure.

## Audit state

**R4.1 — FINAL AUDIT: PASS / CLOSED / APPROVED**

The 2026-09-02 decision supersedes the earlier R4.1 wording that no primary provider had yet been selected. The provider-independent architecture remains valid and is not reopened by this provider selection.
