# P6.2 — Decision Log v1

**Status:** Approved
**Date:** 2026-08-18

## Purpose

Compact production reference for the approved P6.2 decisions. This is not a replacement for the individual component documents; it is the quick consistency check used before advancing the design.

| ID | Approved decision | Key rule |
|---|---|---|
| P6.2.1 | Navigation | Continuous exploration, contextual navigation, responsive adaptation |
| P6.2.2 | Map | Map-first; the map is part of exploration |
| P6.2.3 | Place | Place is the core contextual content experience |
| P6.2.4 | Search & Discovery | Search is a layer of exploration, not a destination |
| P6.2.5 | 360° Experience | 360° is an experience layer, not merely a viewer/feature |
| P6.2.6 | Social, Sharing & Save | Accountless exploration; account-based memory |

## Cross-cutting rules

1. Build for the complete product experience while launching with realistic initial content.
2. Initial content focuses on routes, Google Street View where appropriate, own viewpoint/landscape photography and exterior monument content.
3. The architecture must support future 360° proprietary capture and interior experiences.
4. Géoportail remains an intended future mapping/collaboration integration path; no provider lock-in.
5. Premium identity comes from clarity, restraint, visual hierarchy and practical interaction.
6. No major new screen or component is added without traceability to an approved journey or product decision.
7. The PWA-first strategy remains compatible with future native evolution.

## Account model

- Explore: no account.
- Search: no account.
- View content: no account.
- Share: no account.
- Save: account required.
- Collections: account required.
- Saved Routes: account required.
- My Explore: account required.
- Cross-device synchronisation: account required.

## Quality gate

Before moving to a new P6.2 component:

1. Check this decision log.
2. Check the P6.2 reconciliation audit.
3. Check the relevant PDRs.
4. Confirm the component is actually in the approved plan.
5. Present proposal and explanation.
6. Validate visually.
7. Run audit.
8. Record approval in GitHub.

This gate exists specifically to prevent design drift and accidental invention of unapproved scope.
