# P6.2.3 — Place Component Language

**Status: APPROVED**

## Core principle
A Place is not a record to display. It is an experience to enter.

## Approved decisions
- Photography leads the visual hierarchy.
- Place is expressed through a reusable component family: Preview, Card, Header, Experience, Information, Continue Exploring.
- Place Preview is contextual and lightweight for the map.
- Place Card is designed for discovery and results.
- Place Header introduces the immersive place experience.
- 360° is treated as an experience entry point, not another gallery image.
- Save/favourite is secondary to exploration.
- Story uses progressive disclosure rather than presenting a long information sheet immediately.
- Continue Exploring connects one place to nearby or related places.
- Mobile follows the approved map-first + contextual bottom-sheet model.
- Information adapts to the type of place; there is no universal mandatory metadata sheet.
- The system remains consistent while allowing editorial variety between different place types.

## Information adaptation rule
Information must adapt to the place. Examples include:
- Trails: distance, difficulty, duration.
- Heritage/monuments: period, accessibility, visit duration where relevant.
- Viewpoints: altitude, landscape context, best conditions/time where relevant.
- 360° experiences: availability and experience type.

Metadata must never dominate the place identity or storytelling.

## Deliberately deferred
- Final iconography.
- Exact 360° viewer controls.
- Production content and photography.
- Exact metadata schemas per place type.

## Validation
The visual audit confirmed the Place Preview, Place Card, Place Header, 360° entry, Story, Save, Continue Exploring, desktop/mobile behaviour, and adaptive information principles.
