# P6.3.2 — Buttons & Controls Audit

**Status:** APPROVED
**Phase:** Design System Foundations Completion
**Decision:** The restrained, hierarchical control system is approved. Final numerical tokens remain subject to global consolidation and the accessibility audit.

## Audit purpose

Validate the approved P6.3.2 Buttons & Controls direction against the P6.1 visual language, P6.3.1 iconography, the completed P6.2 component language, mobile interaction requirements and future accessibility work.

## Approved direction

Explore Luxembourg 360 uses a restrained, hierarchical control system where actions are clear, contextual and accessible without competing with the content.

### Action hierarchy

1. Primary — the main action for the current context.
2. Secondary — important supporting actions.
3. Quiet / tertiary — contextual or lower-emphasis actions.
4. Destructive — actions with meaningful negative consequences.

Core rule:

> One primary action per context.

## Supported control forms

- Standard button
- Icon button
- Text action
- Filter / pill
- Segmented control
- Toggle / switch
- Input
- Floating map control
- Bottom-sheet action

Pills are not the default button shape. They are primarily used for filters, categories, selections and compact states.

## Interaction states

Controls support a consistent state model:

- Default
- Hover
- Pressed
- Selected
- Focus
- Disabled
- Loading

Where appropriate, state transitions communicate progress clearly, e.g. **Save → Saving → Saved**.

## Icon integration

P6.3.2 builds directly on P6.3.1. Icons support actions but do not replace labels where the meaning is not universally recognizable.

Icon-only controls are intentionally restricted to familiar actions such as Back, Close, Search, Zoom, Location, More and Fullscreen.

## Mobile and touch

The visual size of an icon or control is not the same as its interactive area. Touch targets must provide sufficient usable space, particularly for navigation, map controls, 360° controls and Save.

Detailed accessibility thresholds will be consolidated in P6.3.6.

## Map controls

Map controls remain contextual and grouped. The map must remain the visual protagonist rather than being covered by a large collection of floating controls.

## Bottom sheets

On mobile, contextual actions can be consolidated in bottom sheets to reduce visual clutter and keep actions close to the relevant place or route content.

## Search and filters

Search inputs use the same restrained visual language. Filters use pill/selection treatment only where semantic filtering or categorisation is involved.

Segmented controls are reserved for mutually exclusive modes, such as Map / List.

Toggles represent binary on/off states and should not be used merely as an alternative visual button style.

## Feedback

Interaction feedback should be immediate, discreet and understandable. The system should communicate progress without intrusive animation or excessive notification UI.

## Relationship to P6.2

## Scope control

The demonstration values for height, padding, radius and touch targets are visual references, not final frozen numerical tokens. These values will be consolidated against the P6.1 token system and P6.3.6 accessibility requirements.

## Audit conclusion

No structural contradiction was found. The only intentionally open area is final numerical token consolidation, which should occur globally rather than being prematurely frozen inside this component.
