# Explore Luxembourg 360 — D-03 Brand Asset Implementation Contract

**Status:** Accepted — Final Pre-Codex
**Scope:** Production brand assets and implementation rules
**Authority:** Explore Luxembourg 360 approved brand/design direction

## 1. Purpose

This document defines the implementation contract for the official Explore Luxembourg 360 brand assets.

The purpose is to ensure that the application uses the project's approved identity consistently and that Codex does not invent, redraw, replace or reinterpret the logo as part of implementation.

## 2. Source of truth

The official Explore Luxembourg 360 logo and approved brand materials supplied by the project owner are the only authoritative brand assets.

The implementation repository must contain a controlled production asset location once application code is introduced. Recommended location:

`apps/web/public/brand/`

The final asset files must be copied from the approved project-owned source material; they must not be regenerated by Codex.

## 3. Required asset package

The production package should contain, where supplied and legally cleared:

- primary logo;
- approved monochrome/light/dark variants, if supplied;
- SVG master(s), where available;
- raster fallback(s), where required;
- favicon/app icon assets derived from the approved mark, not a newly designed symbol;
- any approved wordmark/lockup variants needed by responsive layouts.

Do not create additional logo variants merely for visual convenience.

## 4. Usage rules

Codex and application developers MUST:

- use the approved logo asset without altering its proportions or geometry;
- preserve required clear space;
- use only approved colour variants;
- preserve legibility across light and dark surfaces;
- use the appropriate supplied variant rather than applying arbitrary filters or CSS recolouring;
- provide an accessible text alternative where the logo is informative or interactive;
- keep brand assets separate from generic UI icons.

Codex MUST NOT:

- generate a replacement logo;
- redraw the logo in CSS or SVG from memory;
- alter the mark's geometry;
- add gradients, shadows, outlines or decorative effects to the logo;
- substitute a generic map pin, compass, globe or other symbol for the official mark;
- use an AI-generated logo as the production identity.

## 5. Asset quality and technical requirements

Production assets must be validated for:

- correct dimensions/viewBox for SVG;
- crisp rendering at high-density displays;
- transparent background where required;
- correct colour values;
- reasonable file size;
- no embedded secrets or tracking code;
- no unexpected external resource dependencies.

SVG files should be treated as untrusted input and sanitised/validated before use if they originate from an external source.

## 6. Responsive usage

The logo must have deliberate responsive behaviour rather than being scaled indiscriminately.

Desktop, tablet and mobile layouts may use different approved lockups only where those variants exist in the official asset package.

The brand must never dominate the map, territory or editorial content. Explore Luxembourg 360 is an exploration product; branding supports orientation and recognition rather than becoming the primary visual object.

## 7. Relationship to the design system

D-03 is subordinate to the approved visual language and D-01/D-02 contracts for typography and design tokens.

The logo is a brand asset, not a source of arbitrary UI colours. Components must continue to consume semantic design tokens rather than copying colours sampled from the logo.

## 8. Licensing and provenance

The final repository asset package must record the provenance and usage rights of each non-trivial brand asset.

Codex must not add third-party logos, fonts, photographs or icons to the production package without an approved source and compatible licence.

## 9. Acceptance criteria

D-03 is considered implemented when:

1. The official project-owned logo files are available in the controlled application asset location.
2. The asset provenance/source is documented.
3. Required variants are identified and no unapproved variants exist.
4. The web application references the approved assets directly.
5. The logo passes desktop/mobile, light/dark and accessibility review.
6. No replacement/generated logo is present.

## 10. Codex instruction

> **Use the official Explore Luxembourg 360 brand assets exactly as supplied. Never invent, redraw, replace or stylistically reinterpret the logo. If a required variant is missing, stop and request a project-owner decision rather than creating one.**
