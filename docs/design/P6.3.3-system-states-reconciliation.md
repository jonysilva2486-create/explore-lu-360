# P6.3.3 — System States Reconciliation

**Status:** OPEN — REQUIRES PROJECT REVALIDATION
**Reason:** The current GitHub audit trail does not contain a canonical P6.3.3 System States audit, although the original P6.3 plan explicitly defines this as the third foundation.

## Required scope

P6.3.3 must define the visual and interaction language for at least:

- Loading
- Error
- Empty
- Offline
- Unavailable
- Permission-related states

It must define how these states communicate clearly without excessive UI or decorative motion, and how they integrate with P6.3.1 iconography and P6.3.2 controls.

## Current evidence

The approved Motion work references System States conceptually, but that does not substitute for a dedicated P6.3.3 proposal, visual demonstration and audit.

No approval is invented by this reconciliation record.

## Required process

Before P6.3.3 can be marked closed:

1. proposal and explanation;
2. visual demonstration;
3. explicit project approval;
4. audit;
5. final GitHub record.

## Relationship to later points

P6.3.5 Motion and P6.3.6 Accessibility may reference System States, but P6.3.3 remains independently responsible for defining what each system state communicates.
