# P6.3.1 — Iconography Audit

**Status:** APPROVED
**Phase:** Design System Foundations Completion
**Decision:** Iconography language approved; technical library and final exhaustive inventory remain open.

## Audit purpose

Validate the approved P6.3.1 iconography direction against the Explore Luxembourg 360 visual identity, existing P6.2 components, future Design System foundations and the project's real content strategy.

## Approved direction

Explore Luxembourg 360 uses a restrained, outline-first icon system designed to support exploration without competing with the places themselves.

### Core principles

- Outline-first visual language.
- Consistent stroke and geometry.
- Minimal, premium and contemporary appearance.
- Icons support content; they do not compete with it.
- Filled variants may be used for meaningful active/selected states, not decoration.
- SVG/vector is the implementation direction.
- Icon language is functional first and contextual second.
- Decorative icon use should be exceptional.

## System boundaries

### UI icons vs map markers

UI icons and map markers share the same visual language but are not the same system. Map markers have additional requirements for map contrast, zoom levels, clustering and selection.

### 360° hotspots

360° hotspots must remain spatially integrated and visually restrained. They should feel like points of discovery inside the experience rather than ordinary application buttons placed over an image.

### Accessibility

An icon must not be the sole carrier of essential information when the meaning is not universally recognizable. Functional icons require accessible naming, focus treatment, appropriate contrast and adequate interactive areas. Detailed accessibility values will be consolidated in P6.3.6.

## Scope control

The visual demonstration contains representative icons such as viewpoint, heritage, nature, hiking and 360°. These examples do not automatically become mandatory Core Icon Set members.

The final inventory will be consolidated during Design System implementation and should follow a controlled Core → Extended → Custom model.

## Technical library decision

No specific icon library is frozen by this audit. The project approves the Explore iconography language first and will select the implementation library only after evaluating its ability to reproduce that language cleanly and maintainably.

## Relationship to P6.3.2

P6.3.1 defines the icon language and icon behaviour. P6.3.2 will define how icons live inside buttons and controls, including containers, labels, interaction states and hierarchy. These decisions must remain separate.

## Audit conclusion

**P6.3.1 — Iconography is APPROVED BY AUDIT.**

No contradiction was found that requires changing the approved visual direction. The only intentionally open decisions are the concrete technical icon library and the final exhaustive icon inventory.
