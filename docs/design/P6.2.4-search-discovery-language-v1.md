# P6.2.4 — Search & Discovery Language v1

**Status:** Approved
**Date:** 2026-08-18
**Phase:** P6.2 — Component Language

## Decision

Search is an exploration layer, not a destination. Users can search when they know what they want and discover when they do not.

## Experience model

**Search → Suggestions → Results → Map / Place → Explore → Continue Exploring**

Search must preserve geographic and exploratory context rather than creating an isolated administrative search page.

## Principles

- Search is a universal discovery entry point.
- Suggestions anticipate intent without overwhelming the interface.
- Results prioritise relevance, context and location rather than endless lists.
- Filters are progressive and contextual: simple by default, powerful when needed.
- Near Me / location is requested only when there is a clear reason; denying location does not block exploration.
- Search can lead directly to a Place, Route or 360° Experience.
- The same visual language is shared across mobile and desktop, while interaction patterns adapt to context.

## Semantic search and AI

The initial search can rely on structured text, categories and geographic data. Semantic search and AI-assisted natural-language interpretation may be introduced later without making the MVP dependent on AI.

The initial technical implementation should remain open until the architecture/engineering phase selects the appropriate search strategy and provider.

## Relationship to other components

- Search → Map preserves geographic context.
- Search → Place uses the approved Place Component Language.
- Search → 360° enters the approved 360° Experience Language.
- Search can feed the Save / Collections flow once the user chooses to retain a discovery.

## Responsive behaviour

### Mobile

Prioritise quick search, suggestions, results and contextual map/Place access.

### Desktop

Use additional space for map context, richer result presentation, comparison and planning without turning Search into a dashboard.

## Explicit exclusions

Search does not require AI, advanced personalisation or social ranking for MVP. No public like-based ranking is introduced.

## Core principle

> **Search when you know. Discover when you don't.**

and:

> **Search is a layer of exploration, not a destination.**

## Traceability

This decision is subordinate to the approved Product Vision, PDR-005 Screen Inventory + MVP User Flows, PDR-006 Visual Language and the existing architecture/product decisions.
