# P6.2.2 — Map Component Language v1

**Status:** Approved
**Date:** 2026-08-18
**Phase:** P6.2 — Component Language

## Decision

The map is a primary exploration surface, not merely a utility. The product follows a **map-first** model while preserving direct access to places, routes, search and 360° experiences.

## Visual and interaction principles

- Contemporary atlas character rather than a generic navigation app.
- Progressive zoom: reveal detail as the user moves closer.
- Contextual clustering rather than a permanent field of pins.
- Selection is visual and contextual; selecting a place opens its Place Preview without losing geographic context.
- Desktop prioritises map context with contextual side content where useful.
- Mobile prioritises the map with a contextual Bottom Sheet.
- Controls remain minimal and appear when needed.
- The map must never become a dead end: Map → Place → 360° / Story → Continue Exploring → Map.

## Content and platform strategy

The initial product can combine geographic data and imagery from appropriate sources, including Google Street View where relevant to routes and public coverage. The experience layer, place language and exploration flow remain owned by Explore Luxembourg 360.

The architecture should remain capable of integrating **Géoportail** as an important future/public-sector mapping and collaboration layer without making the product dependent on a single provider.

## Responsive behaviour

### Mobile

- Map remains the dominant surface.
- Bottom Sheet provides contextual place/route information.
- Controls are reduced to essential actions.
- Location is requested only when genuinely useful.

### Desktop

- Broader geographic context is visible.
- Search, comparison and planning can use additional screen space.
- Contextual panels must not obscure the map unnecessarily.

## Accessibility and states

The map language must support loading, error, offline/limited-network, permission denied, empty-result and slow-network states as first-class product states.

## Explicit exclusions

This component does not define advanced turn-by-turn navigation, advanced route tracking or advanced offline region management. Those remain outside the MVP unless separately approved.

## Core principle

> **The map is not a tool. It is one of the places where exploration happens.**

## Traceability

This decision is subordinate to the approved Product Vision, PDR-005 Screen Inventory + MVP User Flows, PDR-006 Visual Language and the existing architecture/product decisions.
