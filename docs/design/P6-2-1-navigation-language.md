# P6.2.1 — Navigation Language

**Status:** APPROVED
**Phase:** P6.2 — Component Language
**Decision:** Approved by product owner

## Purpose
Define how navigation behaves across Explore Luxembourg 360 without competing with the place, map, story or immersive experience.

## Core principle
> Navigation is not a destination. It is a guide.

## Desktop
- Use a single, discreet contextual header rather than a permanent sidebar.
- Keep brand/home accessible.
- Keep primary navigation short and predictable.
- Search and secondary actions remain available without dominating the interface.
- On Place views, navigation becomes contextual to the place.
- On 360° experiences, interface recedes so content takes the stage.

## Mobile
- Map-first exploration model.
- Persistent bottom navigation with five core destinations: Explore, Map, Saved, Trails, Account.
- Search remains readily available during exploration.
- Contextual content appears through the place sheet when relevant.
- Secondary/less frequent functions live in the contextual menu.

## 360°
- Navigation fades into the background.
- Keep only controls necessary for orientation, essential actions and exiting the experience.
- The immersive content is the primary interface.

## Responsive behaviour
Responsive design changes behaviour, not merely dimensions. Desktop and mobile share the same product model but use interaction patterns appropriate to their screen and input method.

## Approval
The product owner reviewed the visual demonstration of the desktop header, mobile navigation, Place contextual navigation and 360° behaviour and approved the direction without structural changes.
