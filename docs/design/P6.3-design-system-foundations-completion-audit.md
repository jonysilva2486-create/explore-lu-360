## Reconciliation decisions

Earlier working documents contained a numbering drift in which Motion and Typography had temporarily occupied incorrect P6.3 positions.

The final canonical structure is:

1. Iconography
2. Buttons & Controls
3. System States
4. Light / Dark Behaviour
5. Motion
6. Accessibility

Typography & Content Hierarchy is retained as a refinement of **P6.1 Visual Language**, where it belongs in the wider design-system structure. It is not a P6.3 subsystem.

## Important final decisions

### System States

The system defines Loading, Empty, Error, Offline, Unavailable and Permission states, with recovery paths and scope-aware behaviour. A failure of one experience layer should not unnecessarily block the entire place experience.

### Light / Dark

Light and Dark are two expressions of one Explore Luxembourg 360 visual language, not separate identities.

Dark Mode uses a **soft / near-black foundation**, not deep absolute black as the default global background. Surface hierarchy must remain visible through tonal differentiation.

### Motion

Motion supports orientation, continuity and feedback. It must remain restrained and respect Reduced Motion.

### Accessibility

WCAG 2.2 AA is the product target. Accessibility is treated as a design-system requirement, while technical conformance remains subject to implementation testing.

## Initial-content compatibility

The system is designed to support the initial production reality:

- routes;
- Google Street View;
- exterior photography;
- viewpoints;
- exterior monument documentation;
- place information.

It is also architecturally prepared for future richer experiences, including own 360° capture and authorised interior mapping, without requiring a new visual system.

## Implementation boundary

P6.3 being closed does **not** mean that implementation testing is complete. During development, exact token values, contrast, keyboard/focus behaviour, screen-reader announcements, map rendering, device behaviour, motion and performance must still be validated.

## Conclusion

**P6.3 — Design System Foundations: CLOSED / APPROVED.**

No additional P6.3 design item remains open. Future refinements discovered during implementation must be recorded as implementation refinements or controlled design changes rather than silently reopening the completed foundation.
