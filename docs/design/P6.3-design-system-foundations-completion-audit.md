## Important planning correction

There is currently no previously approved `P6.2.7` in the project plan.

The six P6.2 components are complete. The next work should therefore address the remaining PDR-006 design-system foundations rather than inventing another P6.2 component.

The label **P6.3 — Design System Foundations Completion** is a proposed organisational label for this next block and must not be treated as an already-approved historical plan item.

## Proposed next sequence

The following sequence is recommended because of dependency and validation order:

### P6.3.1 — Iconography
Define icon language, visual weight, sizing, alignment, states and usage rules.

### P6.3.2 — Buttons & Controls
Define button hierarchy, controls, interaction states, sizing, touch behaviour and usage rules.

### P6.3.3 — System States
Define loading, error, empty, offline, unavailable and permission-related states.

### P6.3.4 — Light / Dark Behaviour
Define how the approved visual language behaves across light and dark surfaces and states.

### P6.3.5 — Motion
Define motion tokens, transition principles, duration/easing guidance, continuity patterns and reduced-motion behaviour.

### P6.3.6 — Accessibility
Consolidate accessibility rules across the design system, including contrast, focus, keyboard interaction, touch targets, semantic hierarchy, reduced motion and non-map alternatives for essential information.

This sequence is a recommendation pending explicit approval; it is not yet a set of approved implementation decisions.

## Brand reconciliation gate

PDR-006 requires the existing official Explore Luxembourg 360 brand assets to be reconciled before final production tokens are frozen. No replacement logo or silent identity change is permitted.

## Content reality constraint

All design-system decisions must remain compatible with the actual initial content strategy:

- routes using Google Street View where appropriate;
- own photography of viewpoints, landscapes and places;
- exterior monument content initially;
- future own 360° production and interior mapping through permissions and collaborations.

The platform must be prepared for the complete future experience without assuming that all advanced content exists at launch.

## Quality gate

Before starting any new P6.3 sub-point:

1. verify the point against the reconciled plan;
2. present the proposal and explain the reasoning in accessible language;
3. provide a visual demonstration where useful;
4. perform the audit before approval;
5. record the final decision in GitHub;
6. only then proceed to the next point.
