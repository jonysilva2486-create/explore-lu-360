# P6.1 — Visual Validation Audit

**Status:** Proposed / Validation in progress  
**Date:** 2026-08-18  
**Reference:** Explore Luxembourg 360 — P6.1 Design Tokens & Visual Language

## Purpose

Validate the conceptual visual mockup produced for P6.1 before freezing the design tokens. The mockup is a visual reference, not a production UI specification.

## What the mockup successfully validates

### 1. Overall identity — APPROVED DIRECTION

The combination of editorial typography, restrained earthy colours, cartographic treatment and immersive photography communicates the intended identity:

**Digital Atlas + Editorial Travel + Immersive Technology.**

It does not resemble a generic tourism website or SaaS dashboard.

### 2. Photography — APPROVED DIRECTION

Photography is treated as primary content rather than decoration. Large visual areas create a sense of place and make the destination the dominant element.

### 3. Cartography — APPROVED DIRECTION

The map is visually integrated into the product rather than appearing as an unrelated embedded service. Its palette is restrained and compatible with the editorial interface.

### 4. Typography — APPROVED DIRECTION

The serif display treatment combined with a clean sans-serif interface creates the intended balance between heritage/storytelling and technology/precision.

### 5. Accent colour — APPROVED DIRECTION

Copper is effective as a restrained action/selection accent. It must remain a small percentage of the interface and must not become a decorative dominant colour.

### 6. Mobile/desktop relationship — APPROVED DIRECTION

The conceptual mobile view is not merely a compressed desktop layout. It demonstrates the intended principle that responsive design changes composition and interaction behaviour.

### 7. 360° experience — APPROVED DIRECTION

The visual treatment supports a dedicated immersive mode rather than presenting 360° imagery as an ordinary gallery item.

## Things NOT to treat as final decisions

The following elements in the mockup are illustrative only and require separate specification:

- exact logo construction and placement;
- exact navigation labels and order;
- exact map provider/style;
- exact icon library;
- exact component dimensions;
- exact typography choice and licensing/technical availability;
- exact photography/content;
- exact mobile navigation pattern;
- exact button dimensions;
- exact metadata shown for a place;
- any 3D map behaviour;
- exact 360° controls.

## Important brand dependency

The official Explore Luxembourg 360 brand assets must be reconciled with the proposed tokens before the final visual system is frozen. The repository currently does not contain the official brand asset package.

## Audit result

**PASS — visual direction validated.**

The mockup provides a strong reference for the intended visual character. No fundamental change to the P6.1 direction is required at this stage.

The next action is to formalise the design tokens and test them against the four priority contexts:

1. Explore / Map
2. Place
3. 360° Experience
4. Mobile Explore

Only after those validations should P6.1 be frozen as an implementation-ready design-token specification.
