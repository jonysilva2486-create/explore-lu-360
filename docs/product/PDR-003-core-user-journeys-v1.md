# PDR-003 — Core User Journeys v1

**Status:** Accepted
**Date:** 2026-08-18

## Decision

Explore Luxembourg 360 will define six core user journeys, with a deliberate priority hierarchy.

### Level 1 — Core product experience

1. **Discover a place** — explore the territory, open a place, understand it through story and media, experience 360° where available, and continue to related discoveries.
2. **Explore around me** — optionally use device location to discover relevant places nearby without making location permission mandatory for the platform.
3. **Enter a 360° experience** — move from a place into an immersive experience and use contextual links/hotspots to continue exploring.

### Level 2 — Deeper exploration

4. **Discover a trail/route** — find a route, understand it, explore places associated with it, and save it where useful.

### Level 3 — Personal continuity

5. **Save and continue** — save places, routes or collections and access that state later and across devices through the shared account/data model.

### Level 4 — Ecosystem contribution

6. **Contribute** — contribute photographs, observations or information from within an exploration context, subject to rights, privacy, quality and moderation controls.

## Journey principles

- Exploration is the primary activity.
- A user should be able to begin exploring without creating an account.
- Location permission is requested only when a feature genuinely needs it.
- 360° is an exploration layer, not merely a gallery format.
- Places, routes, stories, media, regions and experiences should form a connected exploration network rather than isolated content categories.
- Contribution should emerge naturally from exploration and must not dominate the first-use experience.
- Secondary journeys must not unnecessarily complicate the primary discovery journey.

## Product model

The core loop is:

**Explore → Know → Continue exploring**

with personal and community layers:

**Explore → Know → Save / Contribute → Preserve**

## Responsive interpretation

The journeys remain the same across devices, but their interaction model adapts to context.

### Mobile

Prioritise location-aware discovery, map interaction, quick place access, media/360° and exploration in the field.

### Desktop

Prioritise broader map context, search, comparison, detailed stories, planning and richer exploration workflows.

## MVP implication

These journeys define the basis for the next decision: separating capabilities required for the first viable product from capabilities intentionally deferred to later phases.

No implementation should be considered justified solely because it is technically possible; it should support one or more of these journeys and have a clear product purpose.
