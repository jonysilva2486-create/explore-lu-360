# Explore Luxembourg 360 — R4.1 Mapping Provider Validation

**Status:** REFINED / AWAITING FINAL AUDIT  
**Parent:** R4 — External Infrastructure & Providers

## Purpose

Validate the mapping/provider strategy for the first vertical slice without reopening the approved provider-independent geospatial architecture.

## Core decision

Explore Luxembourg 360 will not make one external provider the definition of its geographic model. PostgreSQL/PostGIS remains authoritative for project-owned geographic data. External sources/providers are accessed through an internal geospatial abstraction boundary.

## Candidate roles

### Mapbox
Strong MVP candidate because current free tiers provide meaningful headroom for web map loads, Directions, Map Matching and temporary geocoding. Permanent geocoding is not treated as a free capability and must not become an implicit MVP dependency.

### MapTiler
Strong technical candidate for vector/raster maps and related services. Its Free plan is suitable for testing/personal/non-commercial use, but is **not** treated as the commercial production solution. Commercial production requires the appropriate paid plan.

### Google Maps
Not the default basemap architecture. Google remains a strategic provider for Street View and may be used through Maps Embed for low-cost MVP integration where appropriate. Billable dynamic Google Maps APIs are introduced only when their additional control/capability is explicitly justified.

### OpenStreetMap
OSM data remains an important ecosystem/source. The public OSM tile servers are not treated as production tile infrastructure. Any OSM-derived service must respect its applicable attribution, caching, capacity and usage policies.

### Géoportail / ACT
Potential authoritative Luxembourg geographic layer. The project has contacted Géoportail/ACT to determine the appropriate technical and institutional integration route. This remains an external dependency and must not block unrelated R4 work.

## MUST HAVE — first vertical slice

- Web/mobile map rendering.
- Project-owned Place and Route geometries from PostGIS.
- Required official Luxembourg layers where available and permitted.
- Basic map interaction and required layers.
- User location display when permission is granted.
- A clean boundary to the Google Street View Experience.
- Provider abstraction so the map provider can be replaced without redesigning the domain model or R3 experience.

## SHOULD / FUTURE — not automatic MVP scope

- Advanced routing.
- Advanced geocoding/search.
- Permanent geocoding storage from third-party providers.
- Automated map matching beyond the concrete route-production need.
- Elevation services.
- 3D terrain.
- Advanced navigation.
- Provider-specific premium features.

A provider's feature catalogue must never silently expand product scope.

## Free-first / cost-controlled rule

During MVP validation, prefer free, open-source and free-tier options when they satisfy the approved requirements. Paid services are introduced only when a concrete product requirement, commercial licence, reliability need or scale constraint justifies the cost.

No recurring provider cost is assumed merely for convenience while project viability is still being validated.

## Provider abstraction rule

Provider-specific SDKs/APIs must not leak through Product/UI/domain contracts. The application should depend on internal capabilities such as map rendering, layers, geocoding or routing interfaces, with provider adapters behind that boundary.

## Current position

No final basemap provider is selected yet. Mapbox and MapTiler remain the principal basemap candidates; Géoportail/ACT remains strategically important for official Luxembourg data; OSM remains a source/ecosystem rather than direct production tile infrastructure; Google Street View remains the principal external 360° Experience provider.

The final provider decision should consider:

1. technical proof against the R3 vertical slice;
2. cost at small, medium and successful-growth usage levels;
3. commercial/licensing conditions;
4. Luxembourg-specific data needs;
5. lock-in and provider replacement effort;
6. the response from Géoportail/ACT when available.
